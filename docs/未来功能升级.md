## 0. 文档定位

本文件收录 DrawHub 全部**尚未实现**的功能设想，按「近 / 中 / 远期」与「技术 / 产品 / 生态」分类，每个条目给出：

- **目标**：解决什么问题
- **现状 / 痛点**：为什么还没做
- **设计要点**：核心做法、依赖与风险
- **验收标准**：怎样算 Done
- **预估工时**：粗略人力（人日）
- **关联模块**：涉及哪些文件

跟踪方式：每个条目对应 `docs/TaskList.md` 的子任务 / GitHub Issue；状态变更请同步到本表「状态」列。

## 2. 中期规划（v0.6 — v0.8，3~6 个月）

## 3. 远期愿景（v1.0+，6 个月以上）

| 名称 | 愿景描述 | 触发条件 |
|------|----------|----------|
| DrawHub Cloud | 用户可选云端备份（E2E 加密），但本地优先策略不变 | DrawHub 月活 ≥ 1 万 |
| 插件市场 | 第三方可发布「引擎 / 主题 / 工具栏扩展」，主进程通过动态 import 加载 | 用户基数支撑 |
| 移动端壳 | Tauri Android/iOS 包，针对触控优化 Excalidraw 与 mindmap | 移动用户占比 ≥ 30% |
| 桌面端协同（CRDT） | 同一文档多人同设备编辑（同一 Tauri 实例） | 本地协同需求被多次反馈 |
| AI 大纲助手 | 输入自然语言大纲 → 自动生成思维导图 JSON → 落到画布 | 本地 LLM 推理 < 1s |
| 硬件加速渲染 | Excalidraw / 思维导图 切 WebGPU，大图（>5000 节点）目标 ≥ 60fps | WebGPU 在 Chromium ≥ 90% 普及 |

## 6. 评审与变更

本路线图每月评审一次（每月 1 日），评审结果以 PR 形式更新本文件。优先级排序遵循：

1. 用户反馈频率（多 → 高）
2. 维护成本可控（拆包/迁移 < 3 人日/任务）
4. 与「隐私优先 / 纯前端」基线对齐

## 7. 不在本路线图（明确排除）

- ❌ **账号体系**：本项目坚守「数据全部本地、不联网」，账号与同步不在考虑范围
- ❌ **完全替代 draw.io**：draw.io 功能完备，无必要重写
- ❌ **重型协同**：实时多人编辑不在本地优先策略内
- ❌ **付费功能**：MIT 协议，不引入任何付费墙
