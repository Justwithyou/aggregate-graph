# 思维导图引擎替换方案 — simple-mind-map → mind-elixir-core

> 版本：v1.0（2026-09-04）
> 状态：待评审
> 目标文档：`docs/DrawHub 设计文档.md` 1.4 参考项目、`docs/TaskList.md`、本文件

## 1. 背景与触发

DrawHub v0.3.x 思维导图引擎使用 `simple-mind-map@0.13`，在用户实际使用与 POC（`poc/mindmap-compare.html`）实测中已反复暴露以下痛点：

| 痛点 | 复现情况 | 影响 |
| --- | --- | --- |
| 主题字体写死「微软雅黑」 | 即便 CSS `font-family` 设为 Assistant 也无效，smm 把 fontFamily 写到 SVG `<text>` 属性上，需 `themeConfig` 全量覆盖 + 渲染后再补刀 | DrawHub 全局字体规则被绕过，UI 不一致 |
| `view.fit()` 等比缩小整图 | 容器宽度 < 800px 时 fit 把整图缩到 30% 以下，文字「几乎不可读」 | 反复反馈未根治 |
| UMD 包体积 ~6.7 MB | main bundle 拆分后思维导图 chunk 仍 ~1.4 MB | 首屏慢，Tauri 体积膨胀 |
| npm 维护节奏放缓 | 最后一次功能更新 ~2025-04，主要靠 issue 答疑 | 安全修复与平台适配跟不上 |
| 富文本节点 `foreignObject` 性能差 | 节点数 > 200 时滚动掉帧 | 大型导图不可用 |

## 2. 候选引擎调研

| 引擎 | 版本 | 体积 (iife) | gzip | 结构 | 字体可控 | 维护状态 | 评分 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **mind-elixir-core** | 5.15.1 | 91 KB | ~15 KB | 逻辑结构 / 左右导图 | 全局 CSS 直接生效 | 活跃（2026-08 发 5.15.0） | ★★★★★ |
| **simple-mind-map**（当前） | 0.13 | 6.7 MB | ~1.4 MB | 7+ 种结构 | 仅 `themeConfig` 属性 | 低维护 | ★★☆☆☆ |
| markmap | 0.18 | ~250 KB | ~70 KB | 树状（Markdown） | CSS 直接 | 活跃 | ★★★☆☆ |
| jsMind | 0.8.x | ~300 KB | ~80 KB | 树状 | CSS | 稳定但 UI 老 | ★★☆☆☆ |
| butterfly-dag | 4.x | ~700 KB | ~200 KB | DAG | CSS | 活跃但偏图论 | ★★☆☆☆ |
| mermaid | 11.x | 不适用（嵌入即用） | — | 流程图谱系 | CSS | 活跃 | ★★☆☆☆ |

**结论**：以「体积 / 字体可控 / 维护节奏 / 大纲交互贴合度」综合看，`mind-elixir-core` 是当前最理性的迁移目标，与 DrawHub 全局字体栈（Assistant）天然兼容。`markmap` 适合 Markdown 大纲侧，`mermaid` 留给「流程图」引擎接入。

## 3. 目标架构

```
src/components/engines/MindMapView.tsx
    ↓ MindMapAdapter 接口
    ├─ SimpleMindMapAdapter（旧，默认 fallback）
    └─ MindElixirAdapter（新，默认）
src/services/mindmap/dataAdapter.ts
    ├─ smmToMe(node)         # smm.data → me.nodeData
    └─ meToSmm(node)         # 反向（兜底/导出兜底）
src/services/mindmap/types.ts
    └─ 统一的 NodeData / EdgeData
```

### 3.1 数据结构归一

simple-mind-map（`<TREE>`）：

```json
{
  "data": { "text": "...", "rich": false, "expand": true, "uid": "..." },
  "children": [ ... ]
}
```

mind-elixir-core（`<TPC>`）：

```json
{
  "topic": "...",
  "id": "root",
  "tags": [],
  "icons": [],
  "hyperLink": "",
  "children": [ ... ],
  "_parent": { "id": "root" }
}
```

归一字段：

| 概念 | smm 字段 | me 字段 | 归一字段 |
| --- | --- | --- | --- |
| 节点文本 | `data.text` | `topic` | `text` |
| 节点 ID | `data.uid` | `id` | `id` |
| 子节点 | `children[]` | `children[]` | `children[]` |
| 折叠状态 | `data.expand` | me 自动 | `expanded` |
| 富文本 | `data.rich` | me 不支持（plugin） | `rich` |
| 备注 | `data.note` | `tags[]` | `note` |

数据归一层只做「树 → 树」转换，深层结构（图标、超链、备注）单独映射。无 ID 时给 `auto_xxx`，避免 me 报错。

### 3.2 EngineAdapter 接口（已有，复用）

文件：`src/types/index.ts` —— `EngineAdapter<TConfig, TData, TState>`

| 方法 | simple-mind-map 实现 | mind-elixir 实现 |
| --- | --- | --- |
| `init(el, config)` | `new MindMap({el})` | `new MindElixir({el})` |
| `setData(d)` | `mm.setData(d)` | `me.refresh(d)` |
| `getData()` | `mm.getData()` | `me.getData()` |
| `destroy()` | `mm.destroy()` | `me.destroy && me.destroy()` |
| `fit()` | `mm.view.fit()` | `me.scale(0.9) + me.toCenter()` |
| `zoomIn/Out` | `mm.view.enlarge/narrow` | `me.scale(scale * 1.1)` |
| `setTheme(t)` | `mm.setThemeConfig` | 重置 `me.tpc.style.fontFamily` |
| `export(format)` | `mm.export('png')` 等 | `me.snapshot()` → canvas |
| `import(format)` | smm 内置 | 解析 JSON 再 `me.refresh` |

### 3.3 主题与字体策略

- 主题切换只切 CSS 变量，**不** 重新构造引擎；
- `me-tpc` 直接走全局字体栈，无需任何 `themeConfig`；
- 暗色主题通过 `me.tpc.style.color/background` 与根容器 `background-color` 切换；
- 关联线、概要文字通过注入 CSS 覆盖：

```css
me-tpc, me-tpc > div, me-tpc * {
  font-family: var(--font) !important;
}
.map-container .lines path { stroke: var(--line-color); }
```

### 3.4 工具栏与上下文菜单映射

| 工具栏项 | smm | me |
| --- | --- | --- |
| 新增子节点 | `mm.execCommand('INSERT_CHILD_NODE')` | `me.addChild(parent)` |
| 新增兄弟 | `mm.execCommand('INSERT_NODE')` | `me.addBrother(parent)` |
| 删除 | `mm.removeNode` | `me.removeNode` |
| 编辑 | `mm.beginEdit` | `me.beginEdit(target)` |
| 撤销 / 重做 | smm 无原生 | `me.undo / me.redo`（`allowUndo: true`） |
| 拖拽移动 | 内置 | 内置（但不支持跨层级校验） |
| 缩放 | `view.setScale` | `me.scale(s)` |
| 居中 | `view.setCenter` | `me.toCenter()` |

### 3.5 存储兼容

- 旧存档以 `STORAGE_KEYS.MINDMAP` 存储，值为 smm 结构；
- 加载时检测顶层是否存在 `data.text`（smm 特征），若命中则走 `smmToMe` 转换；
- 转换结果写回 localStorage，标 `__migrated_from: 'smm@v0.3'`；
- 提供「以旧格式导出」按钮，应急回退。

### 3.6 性能 & 体积目标

| 指标 | 现状 | 目标 |
| --- | --- | --- |
| mindmap chunk gzip | ~360 KB | < 100 KB |
| 首屏到可交互 | ~2.8 s | < 1.5 s |
| 1000 节点滚动帧率 | ~25 fps | ≥ 50 fps |
| 主题切换闪烁 | 存在 | 无（CSS 变量驱动） |

## 4. 实施分期

#### Phase 0 — 准备（1 PR）

- 加 `mind-elixir-core@5.15.x` 依赖；
- 新建 `src/services/mindmap/` 目录（types / dataAdapter / constants）；
- `MindMapView.tsx` 改为「引擎选择器 + 抽象接口」结构，但默认仍是 smm；
- CI 增加 `engine=mind-elixir` 模式跑通；
- ✅ 验收：默认模式与 v0.3.3 行为一致。

#### Phase 1 — 数据归一（1 PR）

- 实现 `smmToMe / meToSmm`；
- 单测覆盖：中英文、特殊字符、嵌套 5 层、空树、单节点；
- 离线脚本 `scripts/migrate-mindmap.ts`（可选，本地开发者使用）；
- ✅ 验收：归一 100% 往返一致（deepEqual）。

#### Phase 2 — MindElixirAdapter（1 PR）

- 实现 `MindElixirAdapter`，覆盖 `EngineAdapter` 全方法；
- 工具栏调用映射；
- 主题/字体 CSS 注入；
- 并存模式（`?engine=me` URL 参数启用）；
- ✅ 验收：手动 30 分钟创建 → 编辑 → 撤销 → 导出 PNG 全流程无报错。

#### Phase 3 — 切换默认（1 PR）

- 默认改为 `MindElixirAdapter`，smm 降级为 `?engine=smm`；
- 加载旧存档时自动迁移；
- README 加「升级与回退」说明；
- ✅ 验收：冷启动 + 旧数据迁移跑通，性能指标达成。

#### Phase 4 — 清理（1 PR）

- 移除 smm 相关代码、依赖；
- 删除 `simple-mind-map` 节点；
- 更新设计文档/CHANGELOG；
- ✅ 验收：构建产物体积下降 ≥ 250 KB gzip，dev 启动无 smm 相关错误。

## 5. 风险与回退

| 风险 | 概率 | 缓解 |
| --- | --- | --- |
| me 数据模型与 smm 差异导致迁移丢失字段（备注/超链） | 中 | 迁移后给一次性「未迁移字段」toast，让用户复制到本地 |
| me 富文本（图片/表格）不支持 | 中 | 提供「粘贴为纯文本 / 图片以附件形式存储」降级路径 |
| 用户旧习惯依赖 smm 的 fishbone / timeline | 中 | Phase 0-2 保留 toolbar 入口，Phase 4 才移除 |
| me API 后续大改版 | 低 | 锁定 5.15.x，锁文件保留 ≥ 3 个版本；建立 fork 兜底（最坏） |
| 主题切换闪烁 | 低 | 用 CSS 变量驱动 + RAF 内一次性 apply

回退机制：

- Phase 3 之前：URL `?engine=smm` 强制走旧引擎，无需发版；
- Phase 3 之后：保留 `?engine=smm` flag 至少 2 个小版本（v0.5 / v0.6）；
- 数据层面：任意时刻可一键导出 me JSON / 导入 smm JSON。

## 6. 验收标准（Done Definition）

1. 思维导图引擎 chunk gzip 下降 ≥ 250 KB；
2. 1k 节点滚动 ≥ 50 fps（Chromium profiler 测）；
3. 主题切换无闪烁，字体全局统一 Assistant；
4. 旧存档自动迁移零丢失（白名单字段全保留）；
5. `?engine=smm` 仍能作为应急回退；
6. Playwright 烟雾测试（`drawhub-smoke.js`）扩展覆盖 me 路径；
7. 设计文档、README、CHANGELOG 同步更新；
8. 至少 1 位非作者用户完成 15 分钟试用无阻塞反馈。

## 7. 不在本期范围

- 鱼骨图 / 时间轴布局（me 原生不支持，留作 plugin 评估）；
- 富文本节点图片直接嵌入（统一改为附件挂载）；
- 与 mermaid / markmap 跨引擎互通（v0.5+ 再议）；
- AI 自动生成思维导图（v0.6+）。
