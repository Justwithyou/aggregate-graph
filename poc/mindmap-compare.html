包体积 … 字体渲染 …
加载方式：两者均通过本地 vendor 副本（UMD/IIFE 构建）直接引入（不经打包器、不依赖 node_modules 与外部网络），并显式套用 DrawHub 全局字体栈以公平对比字体渲染。
simple-mind-map 实测观察
• 节点文字用 SVG <foreignObject> + <div>，由库内部 CSS 固定宽度（500px 上限）
• 容器尺寸变小后 view.fit() 会等比缩放整图 → 文字被同步缩小到 视觉几乎不可读
• 主题字体写死「微软雅黑」需手动在 themeConfig 全量覆盖（已在本 POC 处理）
• 体积大（UMD 6.7 MB）；npm 体积约 1.4 MB（含富文本/数学公式/导出等插件），稳定但作者已进入低维护
• 内置结构最多：逻辑结构 / 思维导图 / 时间轴 / 鱼骨图 / 组织结构 等 7+ 种
mind-elixir-core 实测观察
• 节点文字用自定义 web components（me-tpc），CSS 直接走全局字体栈，节点框自适应文字宽度
• 提供 scale() + toCenter() 单独缩放画布，不会把文字一起缩小
• 字体栈是「-apple-system, BlinkMacSystemFont, Helvetica Neue, PingFang SC...」，不含 Assistant（可在节点 style.fontFamily 单独覆盖）
• 体积极小（IIFE 91 KB，约 15 KB gzip），作者活跃维护
• 结构以左右展开为主，无现成的鱼骨图 / 时间轴（可基于插件扩展）
一句话总结：用户反馈的「simple-mind-map 问题多、字体显示仍未修复」在本次 POC 中被同步复现（左边画布文字几乎不可读）；mind-elixir 在字体渲染和视觉清晰度上明显更优，是当前最理性的替代候选。
